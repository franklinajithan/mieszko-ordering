# Weekly wastage workbooks

Run this on the Ubuntu Mieszko Ordering worker as its existing Linux user.
It uses the protected worker environment and the CRM URLs in Ordering for all
active MSP stores. The CRM account needs access to Reports → Explorer.

Install LibreOffice Calc if it is missing, then install the timer from the
deployed Ordering checkout.

```sh
sudo apt-get install libreoffice-calc
bash automation/install-weekly-wastage.sh
```

The timer runs every Monday at 08:00 UK time. A run downloads the previous
completed Monday–Sunday's Item Sales, RTC, Wastage and Daily Sales by Department
exports. It creates a processed workbook per store and one combined summary in
`~/Mieszko/Weekly Wastage/Weekly Waste DD.MM.YYYY - DD.MM.YYYY/`. Failed stores
are retried three times total. The dated folder is published only when all
stores pass summary validation. A scheduled run reuses a published week. Use **Redownload week** on a report
card to fetch all source reports again. The page shows each store’s progress.
The previous ZIP stays available until the replacement passes validation.

To run the previous completed week on demand and view the results in the journal:

```sh
sudo systemctl start --no-block mieszko-weekly-wastage.service
journalctl -u mieszko-weekly-wastage.service -n 80 --no-pager
systemctl list-timers --all mieszko-weekly-wastage.timer
```

To recover an older week or choose a different output directory, run the script
as the worker user with `--week-start YYYY-MM-DD` and/or `--output /path`.

```sh
.worker-runtime/venv/bin/python automation/weekly_wastage_job.py --week-start 2026-11-02
```

## Ordering status page and ZIP downloads

Deploy the Ordering web app from the same revision as the updated worker. Set
`WEEKLY_WASTAGE_DIRECTORY=/home/backend/Mieszko/Weekly Wastage` in the **Ordering
web service** environment (use its actual worker output directory), then restart
the web service. The web app needs read access to that directory, its `.status`
subdirectory and the ZIP files. The default worker file permissions allow access
by the worker user. If the web app runs in a container or as a different user,
mount the directory read-only and grant that service account read access.
Enable the directory only on the private office Ordering deployment. The web
service must run as the weekly worker user with write access to the archive
to use **Redownload week**. When the weekly worker uses a separate checkout, set
`WEEKLY_WASTAGE_WORKER_DIRECTORY` to the weekly systemd service’s working
directory. Ordering otherwise uses its own working directory. The scheduled job and manual reruns share a lock, so only
one weekly export can run at a time.

Open **Overview → Weekly Wastage**. The page refreshes every 15 seconds and shows
each run and store status. A completed run offers one ZIP containing the combined
summary and store folders. Run an older week with `--week-start` to create a ZIP
and publish status for any workbooks already generated by the earlier worker.
